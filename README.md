# fpga_design
本项目基于安路 PH1P35 芯片和 HX1P35A 开发板，设计了一套集摄像头采集、实时图像处理、手部跟踪、手势识别和信息显示于一体的视觉交互系统。

项目希望让设备通过摄像头“看到”用户的动作，再将识别结果转换为可显示的信息。系统既能展示图像处理效果，也能识别约定手势，并将手势组合成中文短句，为病房或居家照护场景提供一种快捷表达方式。
系统组成与工作流程
系统主要由摄像头、PH1P35 芯片、HDMI 显示器、OLED 屏幕、按键和水平舵机组成。摄像头采集画面后，图像数据进入芯片进行处理；处理后的画面通过 HDMI 输出，手势识别结果或中文短句则可以显示在屏幕上。

项目采用异构计算结构，即让芯片内部不同的计算单元分别承担不同任务：
- FPGA 视频处理逻辑负责接收摄像头数据、图像增强、运动检测、手部前景统计和画面叠加。
- 自研神经网络加速器 NPU负责执行手势分类网络，完成卷积计算并输出类别分数。
- RISC-V 硬核处理器负责系统调度、手部跟踪结果筛选、识别结果确认和中文短句组合。
可以把这套分工理解为：FPGA 负责快速处理连续画面，NPU 负责判断手势类别，处理器负责管理整个流程并决定如何显示结果。
图像处理与模式设计
系统共设计了 00—11 共 12 种工作模式，通过按键切换，涵盖图像处理演示和手势交互功能。主要模式包括：
1. 基础画面与图像增强：完成摄像头画面采集，并提供自动白平衡、色彩校正、Gamma 调整等处理。
2. 图像效果展示：支持灰度图、边缘检测和卡通化显示。
3. 运动检测：分析画面变化，并对检测到的运动区域进行框选。
4. 手部跟踪：先通过张掌动作确认跟踪目标，再根据画面中的前景信息维持跟踪框。
5. 手势识别：对固定取景区域内的手部图像进行分类，并在 HDMI 画面上显示识别类别和置信度。
6. 手势短句交互：将约定手势转换成中文短句，在 OLED 上显示；特定手势还可控制水平舵机步进。
这些模式共用同一套 FPGA 配置和处理器程序，模式切换在帧边界生效，便于持续显示和演示。
手势识别与自研 NPU
手势识别使用一套面向嵌入式部署设计的轻量化卷积神经网络。模型输入为 96×96 像素图像，输出为 12 个类别；网络采用 INT8 量化，以降低模型数据存储和计算开销。

项目在 FPGA 逻辑中设计了一个可复用的 NPU。该加速器使用四路乘加单元，按网络层的配置依次完成普通卷积、深度卷积和逐点卷积等计算。通过让不同类型的卷积共用计算资源，系统能够在开发板有限的硬件资源内运行整个网络。

为了避免单次识别结果跳变影响使用体验，系统还对连续结果进行时序确认，例如结合置信度门限和近期识别结果，判断是否需要更新当前显示类别。

根据技术文档，板上多次读数显示，NPU 完成一次整网推理约需 70 毫秒；从采集请求到识别结果发布，单次 AI 任务约需 86—96 毫秒。在约 200 次板上小样本测试中，10 类手势按 HDMI 确认类别统计的识别率约为 88%—90%。

项目还在冻结验证集上对部署模型进行了离线评估：1348 张手部裁图的分类准确率为 90.9%。离线裁图评估与实际摄像头使用条件不同，不能直接等同于所有场景下的板上识别率。
手势短句与应用场景
针对听障或言语表达不便者在病房、居家照护中的沟通需求，项目设计了一套约定手势短句功能。使用者在取景区域内做出一个手势，或者依次做出两个手势，系统便根据预设规则查找对应内容，并在 OLED 上显示中文短句。

例如，单个约定手势可以对应“请帮帮我”“我不舒服”或“我想喝水”等高频表达；两个手势按顺序组合，可以表达更具体的需求。系统利用 9 种约定手势，组成 90 句中文短语，让有限的手势类别覆盖更多表达内容。

该功能目前属于实验室场景下的交互演示。它使用的是项目预先设计的快捷编码，不是自然手语翻译，也尚未在临床或照护机构中进行实际应用评估。
项目价值
这个项目将图像处理、神经网络推理、处理器控制和外设交互整合在一块开发板上，形成了从“摄像头采集画面”到“识别动作并输出信息”的完整演示流程。

项目的特点是根据任务性质进行分工：连续的视频处理交给 FPGA，神经网络乘加交给专用加速器，较灵活的判断和交互逻辑交给处理器。它展示了 FPGA 在实时视觉处理、边缘人工智能和辅助交互方面的应用潜力，同时也为后续改进识别稳定性、扩大测试范围和完善照护场景设计提供了基础。。
